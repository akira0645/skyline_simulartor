# Pixel City Simulator

在瀏覽器裡玩的像素風城市經營遊戲。從中央一區開始，花錢買下相鄰土地，鋪路、劃分區、蓋水電和公共設施，看城市自己長大；城裡每一位居民都有名字、工作、車子、吃飯習慣和心情，點一下就知道他在做什麼、想什麼。

- **目前版本**：0.6.0（2026-11-20）
- **每一版改了什麼**：[CHANGELOG.md](CHANGELOG.md)
- **授權**：程式 MIT（見 [LICENSE](LICENSE)）；草地、樹與灌木圖塊來自 Kenney「Roguelike Modern City」（CC0）

## 遊戲內容

| 類別 | 內容 |
|---|---|
| 蓋城市 | 32×32 買地擴張（舊存檔與示範城市保留原範圍）；道路、大道、高架、橋；住宅、商業、工業分區；水電；公車與捷運路線 |
| 公共設施 | 消防、警察、學校、診所、醫院、市場、公園、廟、圖書館、電影院、商場等四十多種 |
| 生活店面 | 烘焙坊、花店、蛋糕店、夜市，各有營業時間和居民上門的理由 |
| 居民 | 名字、年紀、個性、工作與班別、薪水存款、車子、認識的人、生病與就醫 |
| 每天的生活 | 餓了找地方吃、累了少出門、太久沒見人會去找人；有人自己煮、有人常外食、有人叫外送、有人兼職送外送 |
| 交通 | 尖峰時段、塞車、紅綠燈、車禍；工廠到商店的共用貨車、可手動規劃物流路線與配車、實際載貨／庫存與到站補貨、物流倉庫中轉、物流營運報表、公車排隊與塞車班距；車流顏色跟著地圖上真正的車 |
| 經濟 | 稅收、維護費、借款、景氣、物價、民生用品、遊客收入 |
| 目標 | 任務、成就、街區組合手冊、節慶、抉擇事件、挑戰 |
| 現成城市 | 小鎮（加州風）、城鎮（紐約風）、大城市（舊金山風）三座示範城市 |
| 存檔 | 每 15 秒自動存，另有 6 格手動存檔，都存在這台電腦的瀏覽器裡 |

各項規則的數字和細節見 [docs/mechanics.md](docs/mechanics.md)。

## 畫面怎麼看

地圖鋪滿整個視窗，其他東西都浮在地圖上。

| 位置 | 內容 |
|---|---|
| 上方 | 日期時間與速度（暫停、0.25×、0.5×、1×、2×、4×）、天氣、資金與每月收支、人口、三種分區的需求、存檔、選單 |
| 上方第二行 | 說明或訊息，可以按 × 關掉 |
| 下方中間 | 工具列。「查看」是預設：拖曳移動地圖，點一格看資料，滾輪縮放；按 Esc 隨時回到查看 |
| 右邊 | 資料面板：地塊、城市、任務、成就、手冊、路線、物流、紀錄 |
| 左下 | 地圖顯示：一般、車流、污染、地價、路線、供電、供水 |

點住宅或店家可以看到裡面的人，再點名字會打開那個人的卡片：心情、肚子、精神、有伴四條狀態條，現在在做什麼、今天去過哪裡、認識誰、心裡在想什麼。

## 本機啟動

需要 Node.js 20.19+（20.x）或 22.12+，以及 npm。

```sh
npm ci
npm run dev
```

在瀏覽器開啟終端機顯示的網址。若 PowerShell 封鎖 npm.ps1，請改用 npm.cmd。重新安裝套件前，先用 Ctrl+C 停止開發伺服器。

## 測試與建置

```sh
npm run test
npm run build
```

- `npm run test` 先跑一般測試，再跑長時間的城市模擬測試。
- `npm run build` 先單獨檢查模擬核心，再檢查整個程式並輸出到 `dist/`。`dist/` 是一包靜態網頁，放到任何網頁空間都能玩。
- `python tools/draw_tiles.py`（需要 Pillow）重畫 `src/assets/city*.png`。要改建築的圖就改這支程式再重跑。
- `tools/screen-*.mjs` 用無畫面的 Edge 開遊戲截圖，檢查排版、車流和人物卡。

## 專案架構

| 資料夾 | 內容 |
|---|---|
| `src/simulation/` | 純 TypeScript 的模擬核心，不碰畫面。同一顆種子、同樣的操作，結果永遠一樣 |
| `src/rendering/` | 用 PixiJS 畫地圖、建築、人和車 |
| `src/app/` | React 畫面：頂列、工具列、資料面板、文字（`wording.ts`）、選單（`menus.ts`） |
| `src/storage/` | 用 IndexedDB 存檔；格式與檢查在 `src/simulation/SaveData.ts` |
| `src/assets/` | 圖塊。`city*.png` 是自製的，`tiles.png` 是 Kenney 的 |
| `tools/` | 畫圖塊與截圖驗收的工具 |
| `docs/` | 規則細節、設計文件、後續工作 |

## 版本與更新紀錄的寫法

版本號寫成「主.次.修」，例如 0.2.0：

- **修**（0.2.0 → 0.2.1）：只修問題，玩法不變。
- **次**（0.2.0 → 0.3.0）：加了新玩法或新內容，舊存檔還能讀。
- **主**（0.x → 1.0）：正式上架，或舊存檔不能再讀。

每次發版要做三件事：

1. 把 `CHANGELOG.md` 最上面「尚未發布」底下的內容，改成新的版本號和日期。
2. 把 `package.json` 的版本號改成一樣的（`npm version 0.3.0 --no-git-tag-version`）。
3. 把這份 README 最上面的「目前版本」改成一樣的。

`CHANGELOG.md` 的格式固定：最新的版本在最上面，每一版底下只用「新增」「修改」「修正」「移除」四種小標題，每一條寫玩家看得到的變化，一條一句。
