# 後續工作檢視

2026-11-15，依使用者「推上去並看是否有可以繼續完成的內容」檢查。以下尚未實作，按建議優先順序排列。

## 1. 修正被跳過的短時段行程

`CivicVisits.ts` 小學／高中出發時段為 07:00–09:00，但 `calendar.ts` 每 tick 為三小時、從 06:00 開始；`BuildingSystem.recordVisits` 僅在 tick 邊界呼叫行程規劃，會在 06:00 與 09:00 都判定不在時段內。這不是增加活動種類能解決的問題。

下一批應讓排程能處理兩個 tick 之間開始的時間窗，並保留出發時間，檢查實際到達、返家、重讀檔與工作衝突；測試需涵蓋 07:00 上學、16:00 托育及營業結束邊界。避免僅把所有營業時段加長。

## 2. 存檔讀取失敗後的恢復操作

`AutosaveSession.initialize()` 快取首次初始化結果；失敗後雖能保護原檔，但目前需重新載入頁面才能再嘗試。可以加入明確的「重試讀取」與備份恢復完成後的自動存檔恢復流程，維持未確認恢復前不覆寫原檔。

## 3. 實際瀏覽器驗收與訪客面板拆分

本輪只有型別／建置與模擬測試，瀏覽器工具先前無法確認網址，因此未完成畫面驗收。可先驗證人數按鈕、名單展開／捲動、點人名、切地塊、鍵盤操作與分頁暫停，再把訪客區塊從 `App.tsx` 抽成獨立元件。

## 4. 日常行程的下一個功能階段

前述正確性與驗收完成後，再加入設施間連續行程（辦完銀行直接去市場）、可查看的當日活動紀錄，以及親友邀約。之後才做容量／候診與完整家庭安置，避免一次改動人物、行程及財產三套資料模型。
