# 城市基礎修正與程式整理

狀態：使用者已同意方向；本書面規格待檢閱，尚未實作。日期：2026-11-15。

使用者範圍：修正大型建築的造訪統計與人物入口，並處理前次檢查的六項建議。居民人生與天氣是後續擴充，見 [居民人生設計](2026-11-15-resident-life-design.md)。不要因擴充規劃而遺漏本階段。

## 1. 已確認的現況

- `TileMap` 的大型設施使用主格加三格 `annex`；`anchorOf` 可找回主格。集合住宅另以 `SavedBuilding.block` 表示，不能假設所有大地塊都是同一資料結構。
- `visitCountAt` 與 `inspect` 已嘗試正規化主格，不宜直接斷言它們完全沒有合併。需要以使用者問題重現 2×2 設施、集合住宅及公園組合，檢查每種情境。
- `doorOf` 取第一個可用接路點；一般設施與醫療行程的最後一點仍是主格，沒有保留實際入口格。
- `recordVisits` 依排程路徑終點計數；`CityRenderer` 自行維護畫面內的活動行程，以住家索引為 key。因此「目前訪客」與「月人次」來源不同，且同一家庭難以同時顯示多名訪客。
- `App` 自動讀檔錯誤會被忽略，15 秒自動寫入仍啟動；讀取損壞存檔後有覆寫原資料的風險。寫入錯誤也被忽略。
- `BuildingSystem.load` 清除鄰里不安與任務冷卻，而不安會影響遷入、學校與商業。
- `SimulationClock.advance` 將全部經過時間同步補算，沒有恢復分頁／休眠後的工作量限制。

## 2. 大型建築與訪客

採「建築身分、占地、入口」分離。只修 UI 加總雖快，無法解決入口與行程來源；完整室內尋路超出本次需要。

- 同一座 2×2 設施的四格共用統計、容量、候診及使用狀態；內部以主格為查詢入口，對外不暴露 `annex`。
- 對集合住宅，顯示整個住宅群總數及可展開的每戶資料，保留住戶所在單位，不將四戶合併成一戶。對連片公園，群組視圖加總成員並對人物／行程去重；單格資訊可保留，但須明確標示範圍。
- 所有外緣相鄰道路都是候選入口；選擇從起點可到達、成本最低者。等成本依人物及行程穩定排序分流。唯一入口時允許集中，不能為平均分布而穿牆或繞去不通的路。
- 行程明確記錄目的建築、實際入口格、道路節點與階段；終點座標不再負責識別建築。
- 到達後進入設施使用狀態；建築外可在指定步道／廣場停留，暫不做室內房間尋路。
- 接路改變時重新驗證入口。建築拆除時取消目的地與預約；同地重建不繼承舊建築訪次及預約。
- 一次到達事件只計一次月人次。取消、回程與等待入口不增加到訪數。離開後再次進入可以算新一次；轉診到另一院所各記一次。
- 目前在場、前往中、候診／排隊、回程分開，不能把前往中當作已使用容量。清單按人物識別，不按住家去重。
- 遷移既有月統計時將主格與附屬格的有效條目合併；移除無所屬的失效條目，保留遷移摘要。原資料沒有行程紀錄，無法重建歷史重複計數，不宣稱能精確修復舊月份。

## 3. 行程的唯一資料來源

抽出 `VisitSystem`：模擬核心產生、推進及完成行程，產生到達與離開事件；渲染器只讀快照並插值位置。鏡頭外仍推進，低畫質只減少繪製。初期可用 `(home, slot)` 作相容識別，轉入人生系統時改用永久 `PersonId`。

將遊戲內時段與步行／搭乘時間統一換算成模擬時間；保留可讀的動畫速度設定，但動畫不能改變到達、訪客容量、統計或相遇結果。小於一 Tick 的事件以模擬子時段排序處理。

## 4. 存檔可靠性

- 分開 `loading / ready / empty / failed`。僅 ready 或確認沒有存檔時啟用自動寫入；loading 時先顯示載入狀態並阻止城市操作，避免操作完成後又被晚到的讀檔覆蓋。
- failed 時保留原自動存檔，顯示可重試／使用手動存檔／另開城市的明確選項。另開城市不自動刪除失敗的舊記錄。
- 顯示最後成功寫入時間及錯誤狀態。寫入序列化，避免舊快照晚完成而蓋掉新快照；重複排程可合併到最新快照。
- 寫入成功才更新成功時間。保留前一個可讀的自動備份；配額不足時提示，不自動刪除手動欄位。
- 保存鄰里不安、任務冷卻及新增的有效行程狀態；由存檔重算純衍生資料。新增格式版本並保留舊版預設值，不一直在 v4 下累加未記錄欄位。
- 使用版本明確的解析、遷移與驗證，先在候選狀態完成檢查再替換目前城市。避免解析失敗留下半載入狀態。
- 增加 IndexedDB 邊界測試：讀取失敗、解析失敗、配額／寫入失敗、寫入先後順序及首次載入。

## 5. 時間與效能

- 預設離開分頁時暫停模擬，回來恢復先前速度，重設牆鐘基準，不模擬離線期間。玩家主動暫停不能被自動恢復取消。
- 可見分頁的短暫延遲保留固定步長；限制每次補算工作量，積欠在後續幀處理。偵測到休眠級長時間缺口時暫停並提示，避免主執行緒一次跑完數小時。
- 先量測三座示範城的模擬耗時與長時間測試，再決定 Worker；本階段不因檔案大就引入 Worker。
- 將快測試與長時間模擬分組執行，避免大量長模擬並行導致逾時；使用明確的組別 timeout，不單純放寬全套時間掩蓋退化。
- 多種子長測驗證人口、工作、住房、資金有限值及危機恢復。財政不要求所有災害情境都賺錢；基準城應可維持，斷路修復應恢復可達服務。

## 6. 程式與文件拆分

依序抽出建築占地與入口查詢、VisitSystem、存檔協調器／React hook、設施與居民面板，再拆事件和財政結算。`BuildingSystem` 留下呼叫順序與系統協調，每次抽取以行為一致測試保護，不一次全改。

README 保留啟動與操作入口；新增現況架構／功能狀態，歷史提案與追加紀錄另存為歷史文件並標示日期。規則、數值、測試依據有單一來源，舊描述必須標示已被取代。

## 7. 驗收

1. 大型設施各格顯示相同訪客與月人次；集合住宅群加總正確且保留每戶身份；公園群不重複計人。
2. 多側接路可選不同入口；單側道路只使用可達入口。轉診、送醫、返家同樣通過。
3. 到訪不因縮放、移動鏡頭、FPS、重繪、重讀檔而增加；到達前不計完成造訪。
4. 兩名同住居民可同時有行程；拆掉目的地後沒有幽靈訪客。
5. 損壞存檔與讀取失敗不覆蓋原資料；不安與任務冷卻存讀檔一致。
6. 分頁隱藏、恢復及長時間缺口不形成無上限同步補算，保持暫停選擇。
7. 單元、存檔整合、長時間模擬、建置通過，瀏覽器驗證包含四格點選、出入動線、鏡頭外訪問及恢復分頁。
