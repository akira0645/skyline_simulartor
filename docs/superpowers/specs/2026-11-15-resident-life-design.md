# 居民人生、人際關係與天氣行為設計

狀態：使用者已要求直接實作，生命週期、關係、天氣與四種建築的第一版已加入；本文件仍包含未完成的完整願景。日期：2026-11-15。實際範圍見 [目前實作](../../current-implementation.md)。

## 1. 願景與使用者要求

讓玩家認得幾位居民，知道他們認識誰、為何出門、需要什麼服務，並看見他們成長、搬家、工作、組成家庭、老去與告別。城市規劃會改變人生機會，居民事件則改變城市需求。

使用者新增要求：雨天可能不想騎腳踏車或出門。天氣必須參與行程與交通選擇，而非只加雨滴特效。圖片使用 imagegen 技能產生並評估，正式素材仍須符合現有像素規格。

前置工作為 [城市基礎修正](2026-11-15-city-foundation-design.md)：大型地塊共用統計、多入口、統一訪次來源、存檔與時間處理、程式整理。

## 2. 現有系統與落差

| 現有實作 | 新系統需要改變的地方 |
|---|---|
| 姓名、特質、初始年齡由 seed、home、slot 推導 | 人物有永久身分；搬家、住宅拆除、家庭重組都不能改名或失去朋友 |
| 成人保存在每棟住宅的 people 陣列 | 全城人物表為主資料；家庭、住宅、工作只引用人物 ID |
| 小孩由 childrenAt 推導，不算人口，18 歲後消失 | 小孩是真實人物，成年後延續同一身分、求學與就業 |
| 年齡隨居住時間增加，沒有退休與自然死亡 | 出生／初始年齡獨立於搬入日期，生命階段有明確轉換 |
| 社區凝聚力是住戶與設施的加總分數 | 保留社區指標，但新增具名的親友與共同經歷 |
| 未受服務的疾病事件直接移除一位住戶 | 具備生病、求醫、候診、治療、康復或死亡的過程 |
| 學歷加薪依現居地教育涵蓋範圍 | 學歷是人物持有的成果，搬離學區不會失去學歷 |
| 設施動畫行程存在渲染器、部分按可見範圍產生 | 模擬核心擁有行程；人物在鏡頭外照樣生活與交友 |

以上是程式碼核對結果，不表示新功能已存在。

## 3. 方案比較與建議

| 方案 | 效果 | 代價 |
|---|---|---|
| 僅增加隨機人物台詞和事件 | 容易增加內容，成本低 | 朋友與人生缺乏連續性，難以追查城市影響 |
| **需求決策＋持續行程＋有限關係網（建議）** | 可解釋、可存檔、可測試，適合數千人口城市 | 需要先整理人物、行程和設施容量 |
| 每人完整即時 AI 或每次行動呼叫語言模型 | 表達自由度高 | 計算／服務成本高，重播與平衡困難，對本機城市遊戲不划算 |

採第二案。人物對話由實際事件與原因生成短句；核心模擬不依賴外部 AI 服務。選項與初始數值是遊戲設計參數，不宣稱為真實人口或醫療模型。

## 4. 玩家能觀察到的一天

居民早上原本騎車上班，出門前下雨。他比較交通費、等車與淋雨程度後改搭公車；公車客滿時等待下一班，預估會遲到便記下原因。下午他與同事在有座位的室內活動中心碰面，兩人共同停留才增加熟悉度。

幾週後他們會互相邀約。朋友生病時，可以探望或幫忙買東西。居民成家後需要住房與托育；年長後減少工作、轉向日間照護。親友去世會留下短暫哀傷與可查看的回憶，紀念花園提供告別和探訪場所。

不是每人每天都要發生故事。大多數日子正常生活，重要變化才進人物履歷與城市摘要。

## 5. 人物與家庭

### 永久身分

- `PersonId` 為全城單調遞增的整數，存檔保留 nextPersonId，絕不因搬家重用。
- 保存姓名、出生生命日、特質、偏好、學歷、健康、存款、車輛、家庭與工作引用。舊居民遷移時固定目前顯示的姓名、年齡與特質。
- `HouseholdId` 代表共同生活／扶養單位，與建築分離。同住不自動代表伴侶或親子；不根據姓名推斷性別或關係。
- 配偶／伴侶及親子關係有獨立記錄；成年可搬家、同住、分戶。兒童跟隨監護家庭，不獨自被失業遷出機制刪除。
- 拆房與火災先產生安置需求；搬家是住所變更，遷出城市有明確事件；死亡為終止生命事件，三者不得混用。
- 家庭共用生活支出與扶養責任，個人仍可保留存款及車輛。分戶與遺產轉移必須有對應帳目，不能複製財富。

### 人口與經濟口徑

- 總人口包含兒童、成人與長者；工作人口、實際就業、學生、退休者分開。
- 兒童不找工作、不產生「失業」抱怨、不繳工作所得稅。退休者不算失業。
- 住房按實際居住人數計容量。舊存檔原本不占容量的小孩遷入真實人物後可形成既存超住，暫停新增遷入並逐步安置，不在載入當下刪除家庭。
- 舊居民稅收模型須拆清楚：保留既有成人稅收基準，再定義受扶養者豁免、退休收入及服務支出。新人口不能自動增加所有稅收。
- 解鎖與成就既有領取紀錄保留；遷移新增兒童不在載入當下連發人口獎金，先記錄遷移基準。

## 6. 人生階段與節奏

| 階段 | 年齡 | 主要需求與行動 |
|---|---|---|
| 幼兒 | 0–5 | 家庭照護、托育、健康；行程由照護者陪同 |
| 學齡兒童 | 6–12 | 小學、玩耍、同學與朋友 |
| 青少年 | 13–17 | 中等教育、社團、朋友、未來職涯 |
| 成人 | 18–64 | 就業、進修、社交、成家與照護親友 |
| 長者 | 65+ | 預設退休、社交、照護與健康；後續可加入自願兼職 |

預設維持現有「一遊戲年長一歲」，避免悄悄改掉既有城市節奏。1× 下遊戲一年約 48 分鐘，新生兒成年約需 14.4 小時；4× 約 3.6 小時。因此新城與示範城採混齡人口，讓玩家很快遇到畢業、退休、家庭與長者故事。

另提供建城時選擇的「世代模式」：生命年齡每遊戲年增加四歲，1× 約 3.6 小時可看到新生兒成年，4× 約 54 分鐘。日夜、星期及財政月份維持原速；生命相關成長、孕育、衰老風險統一按生命時間，不可只加快年齡。城市建立後固定此設定並存檔，避免隨意切換套利。

實作使用世界 `lifeDay` 與人物 `bornAtLifeDay` 算年齡；舊成年人允許負出生生命日。生命時間與日常模擬時間明確分開；孕育進度也用生命日，兩種模式接受同一套規則測試。

出生由有育兒意願的成年家庭提出需求，考慮住房、照護、家庭財務與健康；使用持續的孕育／迎接孩子事件，避免一個按鈕瞬間加人口。不強迫所有伴侶生育，單人家庭與無子女家庭正常存在。收養作為後續擴充，不混進首版生育流程。

## 7. 需求、決策與行程

### 決策順序

緊急避險／急救 → 睡眠與必要照護 → 工作或上學 → 就醫及生活補給 → 社交與休閒。已有行程有承諾成本與最短維持時間，避免每 Tick 換目的地。

初期需求為精力、健康、社交、休閒、生活補給五項。候選行程分數由「需求改善、個人偏好、約定、時間、費用、天氣暴露、可達性、剩餘容量」決定。不可達、未開門或不符合年齡／照護條件的行程先排除，不靠極低分掩蓋不合法選擇。

選擇保留前兩項原因，例如「想見朋友」「雨勢太大，改去室內」「公車太久，只好撐傘步行」。同 seed、相同輸入和時間可重現；使用人物、決策序號與事件類型作穩定亂數來源。

### 行程狀態

計畫 → 預約／等待 → 出發 → 到達 → 活動 → 返程 → 結束。可取消與失敗；緊急中斷有原因及清理程序。每個人同時只有一項主活動，陪同照護者與兒童共用關聯行程但仍有各自人物狀態。

`Trip` 保存人物 ID、目的建築 ID、實際入口、方式、開始／預定到達時間、狀態、預約 token、同行人物及決策原因。到達時發出可去重事件，更新統計與社交；單純產生計畫不算拜訪。

目的建築 ID 與地塊索引分離，同地重建使用新 ID。入口選擇沿用前置修正。建築拆除、路線失效、班車客滿會取消或重新規劃，不在地圖上瞬移。

## 8. 天氣與雨天選擇

### 世界天氣

晴、陰、小雨、大雨為首版狀態，氣溫以冷／舒適／熱區分。季節決定轉移權重；每個天氣段維持至少一個遊戲小時，按種子預排下一段並保存段落與起迄時間。使用者能看見簡短預報，不能每一幀擲骰改天氣。初期城市共用一份天氣，不做逐格氣象。

### 出門意願

| 行程 | 小雨 | 大雨 |
|---|---|---|
| 戶外公園、騎車兜風 | 降低吸引力，可縮短或改室內 | 通常改約、在家或選室內休閒 |
| 與朋友約會 | 優先改成雙方可達且有位子的室內場所 | 雙方同意改約，或用居家聯絡維持少量社交 |
| 上班、上學 | 提早出門、換交通方式 | 仍需到達；無替代時可能遲到或請假，有工作／出席後果 |
| 日常補給 | 延後或合併採買；沿用已有網購選項 | 非急需可延後，庫存不足時仍需出門 |
| 非緊急門診 | 考量路程與健康，允許改約 | 允許安全延後，健康狀態仍持續 |
| 急救／必要照護 | 不能僅因雨天取消 | 走急救或可用的安全運送流程 |

### 交通方式

- 雨勢提高步行、腳踏車及機車的暴露成本，腳踏車一般比步行更受影響；有自有汽車才可選開車，公車／捷運必須有可達路線及運能。
- 撐傘、短程、有遮蔽的入口可降低部分步行不適；有車與愛開車不代表所有人都能瞬間取得車輛。
- 機車與腳踏車並非禁止，交通預算、路程、個性與沒有替代方案可能使人仍騎車。
- 公車候車成本含班距、客滿與是否有雨遮。下雨改搭大眾運輸會增加真實載客需求，不能只換人物標籤。
- 出門前可換方式；途中從自行車改公車需先到可停車且可乘車的節點。首版不做這種中途換乘時，維持原方式到最近安全停留點或返回，不讓車輛憑空消失。
- 雨開始時，戶外休閒者可縮短活動或走到避雨處；正在必要行程的人繼續或有理由改道。取消預約應釋放容量。
- 健康影響由寒冷暴露、疲勞等遊戲狀態控制；不直接設定「碰到雨就生病」。首版不新增傳染病接觸網。
- 原有硬編碼的 driver/rider 行為要明確調整為強偏好；在交通不可用或安全需求更高時可例外，並同步文件及測試。

### 畫面與玩家工具

雨滴、濕地反光、雨傘、雨衣為後續圖像需求；低畫質可省略，結果不得改變。顯示居民改搭車與改約原因，以及雨天站點客滿、戶外設施利用下降。新增公車候車亭升級、入口雨遮與室內活動空間，讓玩家能改善問題。

## 9. 人際關係

- 陌生人 → 認識 → 朋友 → 親密朋友，以共同停留、反覆互動與相容偏好發展。夥伴關係只在成年人之間且雙方有意願時進一步形成。
- 候選相遇來自同一場所／時段、同事、同學、鄰里；道路上擦身而過不自動變朋友。共同在場一段時間才有聊天機會；工作地點可形成熟悉度，但不保證友誼。
- 每日每人最多處理少量新互動；單一人物最多保存 24 條活躍非親屬關係，親屬與伴侶另計。滿額時不新增普通關係，先讓最低互動的熟人淡出。重要親友不因容量滿就被隨機刪除。
- 關係邊保存熟悉度、好感、信任、最近互動與重要共同事件。以人物 ID 排序的配對 key 去重，雙方讀到一致的共同關係。
- 邀約有對象、地點、時段、接受／拒絕／改約，兩人都確認後才保留座位；同一人不能被多個約會重複占用。
- 久未互動緩慢疏遠；失約或衝突會暫時降低關係，不能以一次隨機事件直接摧毀長期友誼。
- 喪親、探病、協助照顧孩子等重要事件影響親近者；每人保留最多 32 條一般近期記憶，出生、親子、婚伴與死亡摘要另存為精簡履歷。

## 10. 健康、退休與死亡

健康初期為健康、輕症、重症、恢復中、需長期照護五類，另有疲勞與衰弱指標。疾病影響日程與工作出席；輕症可在家休息或就診，重症需要適當醫療與床位。

診所處理門診、家庭診所支援育兒與照護諮詢、醫院處理住院及急救、照護中心提供長期照護。看病需要道路、營業時間、人力與容量；「範圍內有醫院」不等於已完成治療。醫療人力可先使用設施編制／預算，下一步才接居民職位，避免首版因沒有醫師就完全無法運作。

死亡風險隨生命階段、健康與可用照護改變，不設同年齡全體死亡。就醫與服務改善風險及恢復機會，不保證永生。開局與遷入年齡分散，避免同批人口同時退休／死亡造成無預警崩城。

死亡交易只執行一次：移出活躍人口、釋放職位與床位、取消行程及預約、處理監護與遺產、更新親友關係、建立紀念摘要。家人有短期哀傷及探訪需求，但不讓死亡事件產生無上限負面連鎖。

沒有紀念設施時使用有限的外部殯葬服務並收費，避免城市因缺一棟後期建築立刻停擺。畫面採平和文字與紀念方式，不呈現遺體；提供隱藏個別死亡通知的顯示選項，模擬結果不改變。

## 11. 對應建築與初期職責

尺寸為實作提案，沿用目前 1×1／2×2 系統。容量與成本先集中在設定，完成基準模擬再定價，不把未驗證數字當完成的平衡。

| 建築 | 尺寸 | 使用行為與城市影響 | 狀態 |
|---|---|---|---|
| 公園、廣場、廟 | 沿用 | 戶外相遇、聊天、節慶；雨天使用下降 | 既有建築擴充 |
| 圖書館、文化中心、商場 | 沿用 | 室內活動與雨天替代目的地；容量有限 | 既有建築擴充 |
| 社區活動中心 | 2×2 | 社團、鄰里聚會、約朋友、雨天室內社交；一座設施多入口 | 新增，概念圖 A |
| 托兒所 | 沿用 1×1 | 真正托育名額與接送，照護者釋出時間 | 既有建築擴充 |
| 小學／高中／大學 | 沿用 | 入學名額、實際出席、同學關係及畢業成果 | 既有建築擴充 |
| 家庭診所 | 1×1 | 孕育追蹤、幼兒照護及家庭支持；不取代醫院重症功能 | 新增，概念圖 B |
| 診所／醫院 | 沿用 | 候診、門診、轉診、急救、床位與探病 | 既有建築擴充 |
| 長者照護中心 | 2×2 | 日間照護、長者活動；後續開放住宿床位，與家庭照護互補 | 新增，概念圖 C |
| 紀念花園 | 2×2 | 告別、追思、家族記憶與探訪，與一般公園分開統計 | 新增，概念圖 D |
| 公車候車亭／入口雨遮 | 升級既有站點／設施 | 減少候車和入場暴露，不增建一套重複道路 | 新增升級項目 |

場所統一描述服務類型、可用時段、同時容量、每日處理量、雨天暴露、入口及費用。候診長度、已預約、在場人數與每日服務人次不可混用。雨遮並不保護整段通勤路線。

## 12. 介面

人物卡以「現在、關係、人生、健康」四頁呈現：現在顯示行程與原因，關係可點選親友，人生列出少量重要事件，健康列出可理解的狀態與求醫進度。固定欄位高度，避免標籤持續跳動。

家庭卡顯示照護者、兒童、長者、住房與支出；設施卡顯示整棟的容量、排隊、在場與月人次。天氣列顯示目前雨勢、下一段預報與受影響交通。城市頁新增年齡結構、扶養負擔、醫療等待與社交孤立指標。

玩家可關注少量居民，重要事件給摘要，其餘進紀錄。關係網先顯示選中人物的一度親友，避免一次畫全城圖造成資訊與效能負擔。

## 13. 模組邊界與運算

- `PopulationSystem`：人物、家庭、遷入遷出與身分索引。
- `LifeSystem`：成長、家庭事件、退休、死亡與扶養轉移。
- `HealthSystem`：健康狀態、治療需求與照護結果。
- `WeatherSystem`：當前及下一段天氣、種子與時段。
- `ActivitySystem`：需求評分、邀約／日程、活動狀態與決策原因。
- `VisitSystem`：路徑、交通方式、入口、到離事件及中斷處理。
- `FacilitySystem`：整棟識別、占地、入口、容量、預約與服務排程。
- `RelationshipSystem`：有共同在場證據的互動、關係衰減與記憶。
- `BuildingSystem`：逐步縮成建築成長與協調入口，既有接口用轉接器維持。

固定步長處理重要轉換；日常需求、健康與年齡更新分批，每個人每天處理固定上限的候選與新互動。以設施／時段分桶找相遇者，禁止全城兩兩比較。路徑快取依路網版本與入口失效；天氣改變先重評還未出發的行程，再按規則處理在途者。

渲染器讀模型快照，不建立會改變結果的訪次或朋友。所有系統輸出 typed events，更新順序固定；同一階段先計畫、再統一提交，避免迭代順序搶走所有床位或相遇機會。緊急醫療優先，其他以等待時間與穩定排序分配。

效能驗證使用 500／3,000／10,000 人固定種子案例，記錄每 Tick 的中位與 p95、記憶體、尋路次數及存檔大小。3,000 人 4× 下以每 Tick p95 小於 50 ms 為初步目標，須記錄機器與設定；尚未量測，不是效能保證。未達標先減少候選、快取與分批，再評估 Worker。

## 14. 儲存與遷移

從 schema v4 逐階段升版：基礎修正先保存有效事件／行程；永久人物表落地時再升版。最終版本號依合併順序指定，不讓不同新結構共用同一版本。

依穩定的住宅、slot 排序分配舊居民 ID，固化顯示姓名、當前年齡、特質、財富、車輛與工作。將當下仍顯示的小孩轉成永久人物，掛在原家庭；不虛構過去已消失的孩子，也不替既有同住成人任意配對。

保存人物、家庭、關係、重要事件、世界生命時間、天氣時段、行程、預約及序號；路徑可在載入後重算，但保留狀態及已發出的事件識別，防止重複到達、出生、扣費或死亡。遷移前保留原存檔，完成參照完整性與容量檢查後才啟用新存檔。

死亡人物保留被親友或紀念冊引用的精簡摘要；未引用且超過保留期的歷史摘要可聚合為城市統計。刪除完整人物前，所有行程、工作、監護、關係與財產引用必須完成轉移或清理。

## 15. 實作順序與可玩里程碑

1. **基礎修正**：先完成已核准的多格建築、統計、多入口、存檔、時間與整理，不先新增人生建築。
2. **人物與行程**：永久 ID、家庭、真實兒童、核心行程、訪次與容量；所有現有交通／工作透過相容層繼續運作。
3. **天氣與交友**：雨天出行選擇、公共運輸運能、共同在場、朋友與邀約，加入社區中心及雨遮。首個可玩故事為「下雨改搭車，與朋友改約室內」。
4. **成長與照護**：求學成果、成年、成家、出生、健康、候診與探病，加入家庭診所。
5. **完整人生**：退休、長期照護、死亡、扶養與遺產、紀念冊，加入照護中心與紀念花園。
6. **平衡與表現**：混齡示範城、多世代壓力測試、正式像素素材與季節／天氣動畫，整理教學。

每個里程碑分開驗收與遷移，不能用尚未完成的後續模組作前一階段的必要依賴。出生、疾病惡化與死亡在各自所需服務及存檔完成後才開放，不先啟用懲罰。

## 16. 驗收案例

1. 搬家、拆房安置、讀檔後姓名／ID／朋友不變；拆房不等於死亡。
2. 兒童成年後保有親子關係並可就學或求職；退休不計失業。
3. 同一家庭兩個人能同時外出；鏡頭外仍能到達、互動及返家。
4. 兩人只路過不算朋友，共同活動可增加熟悉度；一天內不重複刷同一相遇。
5. 施設滿額需等待或改去他處；取消／拆除／死亡釋放全部預約。
6. 雨前雨後同一居民可選不同交通；沒車不能選開車，沒公車路線不能憑空搭車，客滿會等待。
7. 下雨可取消公園行程但不直接取消急救；在途者、腳踏車位置及回程保持一致。
8. 大雨／小雨的決策結果在相同 seed、相同輸入下可重現；存讀檔與改變 FPS 不改變天氣及事件結果。
9. 新生兒只建立一次；死亡清理只執行一次；資產轉移前後守恆，補助或外部費用有記錄。
10. 長時間測試跨 100 生命年，檢查人口來源去向、住房、親友引用、財政有限值與記憶體上限，不要求人口永遠增長。
11. 普通／世代模式的年齡與孕育進度一致縮放；一般財政與日夜周期不加速。
12. 舊存檔遷移不改成年人的姓名、工作與財富；新增孩子不直接刪人、爆發獎金或造成一輪大量遷出。
