# 近看素材載入負擔修正

使用者在建築近看圖更新後回報整個遊戲卡住。先停止新增素材與行為，處理可確認的載入負擔；不把單一記憶體改善當成所有裝置卡頓的完整根因證明。

## 確認的負擔

四張 `city*-detail.png` 都是 2048×2176。以 RGBA8 計，每張像素資料 17 MiB，四張合計 68 MiB，未含 GPU 複本、快取、車輛等。前一版 mount 在首次顯示城市前同時等待四張近看圖，即使視角仍是 1×、只使用一種城市風格。

## 修正

- 首次載入只等待原本一般視角素材；達到 1.75× 門檻才非同步要求目前城市的一張近看圖。
- 等待或載入失敗時沿用原圖與正確 32 px 圖格，不阻塞操作，也不把低解析度圖以 128 px 圖格錯切。
- 一個渲染器最多保留一種近看風格。已載入的同風格圖跨縮放門檻保留，避免來回縮放反覆解碼／GPU 上傳；切換城市風格時釋放舊圖及裁切 Texture 快取。
- 串行處理在途載入與釋放，快速切換城市時捨棄過期結果，離開渲染器後不安裝遲到的圖。
- Pixi Assets 為全域快取，因此近看素材池計算使用者數，避免舊城市卸載仍被新城市使用的同一張圖；新載入也等待同 URL 的在途卸載完成。
- 清理 TileRenderer 的裁切紋理，避免重建城市時累積快取。
- Claude 完成的原風格 128 px 素材未改，模擬、存檔與移動速度未改。

## 驗證與限制

一般回歸 60 檔／238 項通過；之後補強同風格暖快取及跨渲染器共享生命週期測試，最終渲染組重跑 17 檔／59 項通過。正式建置通過，新增來源後的最終 TypeScript 與 Vite 檢查也通過。此輪沒有修改模擬，不重跑長模擬，也不沿用舊結果冒稱本輪重跑。

獨立 origin `127.0.0.1:5204` 使用中型示範城市（約 900 人）驗證初始載入、6× 近看、跨門檻反覆縮放及拖曳。時間持續前進，未重現整頁卡死；測試併跑時讀數約 16 FPS，測試結束後讀到 60 FPS，不能以此作為修正前後 FPS 比較或平板效能保證。截圖 `docs/design-assets/tablet/lazy-atlas-closeup.jpg`。

初版縮小即卸載時，Pixi 會記錄 source/sampler 仍綁定 shader 的釋放警告；最後改為同風格暖快取，重新載入頁面並反覆縮放未新增這些警告。使用者的實體平板及實際卡住時機仍未確認，後續若持續卡頓須針對裝置、路口／車流 CPU、快取尺寸或 WebGL context 診斷，而不是繼續增加圖片解析度。
