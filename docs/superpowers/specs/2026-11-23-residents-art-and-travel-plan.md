# 人物、原風格細化與路程時間：實作前計畫

狀態：先記錄並推送計畫，尚未開始本輪素材或行為修改。現有程式檢查點為 `8383101`（平板縮放修正，已部署）。本文件依使用者要求先供檢視，再開始製作。

## 已確認的方向

1. 人物增加變化，每個人的資料卡顯示對應頭像。
2. 腳踏車與其他建築繼續細化，但必須依照原本風格，不能另做一套風格不同的素材來替換。
3. 使用者選擇「一起放慢時鐘與移動」：1× 約兩分鐘一天，遠距離確實花較多遊戲時間，畫面與抵達事件一致。
4. 沿用程式繪製像素素材與本機 pixel-art-studio／pixel-art-sprites；需要旋轉的車輛沿用 sprite-stacking。保留手繪感，不使用生圖。

## 目前找到的原因

- `streetAppearance.ts` 將多個原始住宅、店面、辦公室等圖格映射到少量通用素材。例如數種住宅都成為同一棟 house，原本屋頂、窗戶、樓層與城市風格的差異因此消失。
- 人物目前主要是同一套身形與姿勢換五種衣色，資料卡沒有頭像；部分地圖外觀依繪製索引選取，不能直接當作居民身分。
- 一個 tick 是三個遊戲小時，現有 1× 每秒一個 tick，約八秒一天。設施訪客依 tick 進度移動，每格步行 0.08 tick，在現有時鐘下約 80 ms；通勤動畫另用每格 1,250 ms，兩者並非同一套計時。
- 貨車有獨立固定步長、庫存與報表時鐘；不能只改日曆秒數就宣稱所有移動與貨運都已一致。

## 第一部分：先校正風格，再擴充素材

### 建築

- 以原有 `city*.png`、原始繪圖程式與四種城市主題為依據，逐格保留：占地、外輪廓、樓層、屋頂形式、門窗分布、招牌與主色。
- 改掉多種建築被同一個細化素材取代的映射。每個原始變體保有身分；縮小與放大觀看時必須仍能認出是同一棟。
- 細節補在原有結構上：瓦片與屋脊、窗框與窗台、陽台欄杆、店面櫥窗、招牌支架、工廠管線、屋頂設備、入口台階。不是單純放大原圖，也不是撒隨機雜點。
- 先做住宅、店面、公共建築各一個「原圖／現有細化／修正細化」對照，再依確認的標準擴充。原有四個 2×2 地標也重新對照；保留完整建築占地，不能拆成四棟小屋。
- 擴充清單依原圖逐格盤點：住宅與公寓各級、商店與辦公大樓各級、工業與倉儲、水電與救援教育、交通設施、生活店面、文化休閒、照護與市政金融、其餘 2×2 建築。沒有獨立完成的項目保留原圖，不用通用素材冒充已完成。

### 人物、頭像

- 建立以穩定居民 ID 為依據的外觀設定；既有居民沒有新欄位時可確定性推導，不能重整、搬家或改繪製順序就換臉。
- 在原有像素比例與色調下變化髮型、髮色、膚色、上衣、下裝與配件，並區分兒童、成人與長者的身形。配件如眼鏡、帽子、背包要有清楚輪廓，避免人人同一套只換色。
- 地圖人物與人物卡頭像共用同一份外觀設定。頭像另外手工程式繪製臉部與肩膀，不把地圖上的小頭直接糊大；也不依名字猜測性別或族群。
- 保留四方向與六步行姿勢，正面、背面、左右方向各自檢查；停下來不持續踏步，轉向不倒退。

### 腳踏車

- 保留原本的瘦車架比例、輪距與色調，補可辨識的前後輪、輻條、車架三角、前叉、把手、坐墊、踏板與鏈條。
- 骨架、車輪和騎士姿勢共用方向定義，檢查正面、背面、側面與斜向；腳踏動作跟行進連動，不以旋轉整張側面圖代替所有角度。
- 車身尺寸依實際外觀，避免因細節增加就擴大碰撞體積；沿用已有的碰撞與跟車規則。

## 第二部分：統一遊戲時間與路程

- 1× 目標為一天約 120 秒，即每個三小時 tick 約 15 秒；保留暫停、0.25×、0.5×、1×、2×、4×。
- 將遊戲分鐘、路徑距離、交通方式、實際經過時間集中換算。核心 tick 的遊戲時長仍為三小時；不為了變慢而改掉年月日和人物年齡的意義。
- 先對齊步行：設施訪客目前每格 0.08 tick，新的時鐘對應約 1.2 秒／格，與現有通勤步行 1.25 秒／格接近。統一來源，消除兩套人物速度的差異。
- 同一路徑下，步行、腳踏車、機車與汽車有各自合理的時間與相對速度。路程越長耗時越多，壅塞、排隊與紅燈增加實際等待；不以瞬移或取消碰撞來追上行程。
- 抵達、開始使用設施、返程和活動紀錄使用同一個進度來源。畫面還在路上時不能先計到訪，也不能資料已回家而人物仍走舊行程。
- 同時檢查通勤、設施拜訪、外送、公車與貨車的時間單位；貨運生產、裝卸、月結與報表不能因時鐘放慢而意外多算／少算十五倍。若需要變更存檔時間欄位，明確遷移並測試舊存檔，不默默重新解讀舊數值。
- 檢查低幀率、不同倍率、暫停、背景分頁與讀檔。長中斷維持原本不補播，素材步行週期依距離更新，避免只把擺腿動畫變慢。
- 地圖格子尚未定義固定公尺數，本輪先統一遊戲內距離與分鐘；不在未定義比例時聲稱已精確模擬幾公里／小時。

## 製作順序與檢查點

1. 推送本計畫與現況紀錄；目前程式與素材不變。
2. 原風格對照樣張：住宅、商店、公共建築、人物與腳踏車，先確認保留下來的比例、輪廓與配色。
3. 人物外觀 ID、人物卡頭像與四方向步行接入；驗證地圖與頭像對應、重整和存讀檔一致。
4. 腳踏車接入，再依逐格清單細化其餘建築；每批附對照圖，避免又出現一個通用素材蓋掉多種變體。
5. 時鐘與路程統一。先小型路徑與到達事件測試，再跑城市模擬，量測效能和經濟變化。
6. 平板放大驗收、各倍率與低幀率驗收，記錄結果後提交、推送並確認遠端部署。

## 驗收條件

- 原圖與細化圖可逐一對應，四種城市主題可辨認，同種不同造型的建築不再被合併；所有改圖有程式來源和預覽。
- 同一人物在地圖、頭像、搬家／重新載入後外觀一致；人物之間有形狀差異，不只換衣服顏色。
- 腳踏車前後方向、騎士坐姿與車架結構合理；碰撞和排隊不退步。
- 1× 約 120 秒一天；同模式下長路徑比短路徑耗時，交通方式速度順序合理；畫面進度、到達事件與人物卡一致。
- 舊存檔可載入，貨物與金錢不因時間換算重複計算；全套模擬與必要回歸通過，建置成功；誠實區分自動化測試、瀏覽器尺寸驗收與實體平板驗收。
